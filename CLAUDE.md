## Architecture
- Site statique HTML/CSS/JS + `server.js` (Node, sans dépendances) qui sert les fichiers et les API.
- `products.json` = source de vérité du catalogue (grilles générées dynamiquement). Champs clés : `id`, `gamme` (`e·boost`/`o·care`/`hydraline`/`o·répare`), `gamme_label`, `badge` (`Bestseller`, `Nouveau`…), `bestseller_rank`, `bestseller:true` (force l'affichage en bestsellers), `category` (`visage` par défaut, `yeux`, `cheveux`, `box`), `image`, `gallery`, `proof`, `ingredients_full`, `bundles`, `box_items`.
- Anciens produits de démo (`serum-eclat-peptides`, `creme-reparatrice-intense`, `essence-hydratante-pro`, `huile-nuit-reparatrice`) **supprimés du catalogue le 07/11/2026** ; leurs URL redirigent en 301 vers le vrai équivalent (`RETIRED` dans seo.js). Les listes `DEMO` restées dans le code sont inoffensives.
- Images : JPG redimensionnés max 1400 px qualité 86 ; miniature panier `cart-<id>.jpg` 560×700. Galerie : nouvelle image principale = en premier partout.
- **Cache images 24 h** (`server.js` : `public, max-age=86400` hors html/js/css/json) → pour REMPLACER une image, lui donner un **nouveau nom de fichier** et mettre à jour les références (sinon l'ancienne reste affichée sur PC). Après modif de products.json, incrémenter `products.json?v=N` dans index.html / soins-*.html (actuellement v=106, harmonisé sur toutes les pages et cart.js).
- Pages catégories : soins-yeux.html et index.html génèrent leurs grilles depuis products.json (rien à ajouter à la main) ; soins-cheveux.html et nouveautes.html ont des cartes **écrites en dur** à ajouter manuellement (+ compteur « N produits » dans soins-cheveux).
- Fiche produit : champ `efficacy` `{claim, stats:[{pct, when}], source}` → affiche les vrais % du test d'usage ; absent → état « Résultats bientôt » (libellés des 3 paliers personnalisables via `efficacy_when`). Si `efficacy.stats` n'a qu'1 valeur → mise en page « solo » premium : grand cercle doré + accroche `desc` (préfixée du %) + texte émotionnel `story` + pastilles `points` (ex. patchs : 98 % après une seule utilisation). Avant/après (`serum-anti-age-peptides`, `serum-gelee-prebiotiques`, `serum-booster-cafeine`, `patchs-yeux-hydrogel-anti-fatigue`, `serum-correcteur-pigmentation`, `creme-anti-age-peptides`) : carrousel en dur dans product.html (`ba-peptides-1/4/2/3-avant|apres.jpg`, 4 slides ; n°4 = testeuse blonde, placée en 2e), défilement auto sans pause au survol (la pause bloquait tout sur PC) ; même photo n°1 réutilisée dans « Ce qu'elles disent » de l'accueil.
- **Performance (06/11)** : `server.js` compresse toutes les réponses texte (Brotli/Gzip, `enableCompression`, cache mémoire par ETag) et répond 304 si le navigateur a déjà la version (accueil 134→30 Ko, products.json 246→36 Ko). Fichiers texte statiques lus d'un bloc pour être compressés ; vidéos/plages d'octets inchangées. Carrousel de l'accueil : la bannière sortante est figée (`pause`) dès le début du glissement, l'entrante est en `hold` (CSS seulement, 3D/particules en attente) puis `play` à la fin ; hors écran tout est en pause (`banner-ctl.js?v=2`, 3 états play/hold/pause). `pump3d.js?v=10` : résolution ≤ 2×, anticrénelage seulement si écran < 2×, qualité adaptative (si images > ~23 ms : 1,5×/1× et 30 i/s). Bannières : halo des particules pré-rendu (plus de createRadialGradient par point), effet de profondeur en `translate` (marge gardée seulement pour les éléments déjà animés en translate, ex. `.ben` peptides), backdrop-filter retiré des grandes pastilles (fond plus opaque), fond rétinol `retinol-photo-1600.jpg` (au lieu de 2110×2800). Mesure : three.js vient de cdnjs (bloqué dans le bac à sable) → pour tester avec la 3D, intercepter `**/three.min.js` vers un three@0.128.0 installé via npm.
- `cart.js` (panier, `data-add-to-cart`, `OnaeCart.addWithFeedback`), `onae-menu.js` (menu mobile premium à onglets + recherche ; version en cache `?v=N` à incrémenter dans toutes les pages à chaque modif ; actuellement v=12, aussi inclus dans product.html et routine.html).
- Gabarit de nouvelle page : head + CSS racine de `fidelite.html` jusqu'à `/* ═══════════ ONAÉ PRIVILÈGE`, + bloc header/menu de `<!-- HEADER -->` jusqu'à la fin du script `onae-menu`, puis CSS/HTML propres, `footer-simple`, `cart.js`, `onae-menu.js`.
- Modules serveur : `accounts.js` (comptes e-mail/téléphone, sessions cookie `onae_sid`, profil, fidélité Rose/Nacre/Écrin, diagnostics enregistrés `/api/me/diagnostics`), `diagnostic.js` (`/api/diagnostic` analyse photo via API Anthropic, photos jamais stockées, résultats dans `diagnostics.json`, `/api/diagnostic/:id`).
- `seo.js` (jamais servi) : fiches produits sur `/produits/<slug>` rendues côté serveur + JSON-LD Product/FAQ/Breadcrumb (301 depuis `product.html?id=`) ; `robots.txt`, `sitemap.xml`, `llms.txt` générés depuis products.json ; canonical/OG/lang injectés dans toutes les pages HTML (après `</title>`, car beaucoup de pages omettent `</head>`). Liens internes produits = `/produits/<id>`. Pas d'`aggregateRating` tant qu'il n'y a pas de vrais avis.
- Espace admin : `/admin` (admin.js) — connexion par formulaire avec NEWSLETTER_KEY (espaces/guillemets tolérés), cookie `onae_admin` 30 j ; tableau des inscrits au concours + modération des avis (Publier/Refuser) + liens exports. Les exports et la modération acceptent ce cookie ou `?key=`. `/api/concours/admin` redirige vers `/admin`.
- Autres API : `/api/contact`, `/api/partner`, `/api/track` (suivi commande via `orders.json`), `/api/newsletter`, `/api/loyalty`.
